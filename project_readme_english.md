# 🧠 Brain Tumor Classification in MRI Using Memory-Optimized ResNet50

This repository contains the implementation and computational optimization of a Computer-Aided Diagnosis (CAD) system for detecting Low-Grade Gliomas (LGG) in Magnetic Resonance Imaging (MRI) scans, utilizing transfer learning (**ResNet50**) and synthetic data augmentation via **Principal Component Analysis (PCA)**.

## 📋 About the Project

Deep learning models pre-trained on *ImageNet*, such as **ResNet50**, require three-dimensional inputs with 3 color channels (`256 x 256 x 3`). However, brain MRI slices are inherently single-channel (grayscale) images.

In traditional literature implementations, the standard workaround consists of statically triplicating the channels of the entire dataset in main memory (CPU/RAM) prior to training. When combined with *Data Augmentation* techniques (such as PCA), this approach drives memory consumption above **20 GB of RAM**, making execution unfeasible on free cloud environments like **Google Colab** (limited to \~12.7 GB of RAM).

### 💡 Proposed Solution (Intra-Graph GPU Channel Expansion)

To enable model training on accessible hardware without altering the mathematical formulation or statistical rigor of the reference study, this project implements an **intra-graph adaptation in Keras**:

1. **Single-Channel Storage in RAM:** Both original images and synthetic samples generated by PCA are kept in main memory as single-channel arrays (`256 x 256 x 1`), reducing the data memory footprint by **\~66% (2/3)**.

2. **On-Demand Dynamic Replication:** A `Concatenate` layer is inserted directly at the network input (`Input -> Concatenate -> ResNet50`), replicating the 3 channels directly in video memory (**GPU VRAM**) solely for the active mini-batch (`batch_size = 10`), with immediate automatic disposal after each iteration.

3. **Explicit Memory Management:** Active garbage collection of intermediate tensors using `del` and `gc.collect()` between pipeline stages and across cross-validation folds.

## ⚙️ Methodological Pipeline

The processing workflow is structured into **7 modular stages** in the `ACI_Projeto_Final.ipynb` notebook:

1. **Library Imports:** Configuration of the TensorFlow/Keras and Scikit-Learn environments, along with GPU availability verification.

2. **Dataset Download:** Automated acquisition of the public *LGG MRI Segmentation* dataset (Mateusz Buda) via `kagglehub`.

3. **Image Processing and Labeling:** Reading of all **3,929 axial slices** and automated binary classification based on medical segmentation masks:

   * **Class 1 (Tumor):** 1,373 images (masks containing pixels $> 0$).

   * **Class 0 (Non-Tumor):** 2,556 images.

4. **Lightweight Data Loading in RAM:** Conversion to grayscale (`.convert("L")`), resizing to $256 \times 256$, and intensity normalization to the $[0.0, 1.0]$ range in `float32`.

5. **Data Augmentation Definition (PCA):** Implementation of latent-space perturbation via the Hadamard product with a $90\%$ noise ratio ($t = 0.1$).

6. **Optimized ResNet50 Architecture:** Model construction featuring a single-channel input, intra-graph `Concatenate` layer, pre-trained ResNet50 *backbone* (`ImageNet`), `Flatten` layer, and a `Dense(1, activation='sigmoid')` output.

7. **Training and Cross-Validation (10-Fold):**

   * Stratified cross-validation (`StratifiedKFold`, 10 folds, `random_state=42`).

   * PCA augmentation applied **exclusively to the training set** within each fold (preventing *data leakage*).

   * Training for **50 epochs** using the `Adadelta` optimizer (`learning_rate=1.0`), `binary_crossentropy` loss function, and `batch_size=10`.

## 🔍 Comparison: Original vs. Optimized Approach

| Component | Original Implementation | Optimized Implementation (This Repository) | 
| ----- | ----- | ----- | 
| **Format in Main RAM** | Static RGB (`256 x 256 x 3`) | Single-Channel Grayscale (`256 x 256 x 1`) | 
| **Channel Expansion** | Single batch on CPU before training | Dynamic on GPU per mini-batch (`Concatenate`) | 
| **Peak RAM Consumption** | \> 20 GB (Exceeds free Colab limits) | < 9 GB (Compatible with free Google Colab T4) | 
| **Mathematical Integrity** | Reference standard | **100% Preserved** (identical weights, filters, and batches) |

## 🚀 How to Run

1. **Open the notebook in Google Colab:**

   * Upload `ACI_Projeto_Final.ipynb` to [Google Colab](https://colab.research.google.com/).

2. **Enable GPU hardware acceleration:**

   * Go to `Runtime` $\rightarrow$ `Change runtime type` $\rightarrow$ Select **T4 GPU**.

3. **Run all cells sequentially:**

   * Dataset download is handled automatically via `kagglehub` in Cell 2 (no manual file uploads required).
